# 대면 실시간 음성 통역 PWA 개발 기획서

> 프로젝트 소유자가 작성한 원본 기획서입니다(2026-11-27 대화에서 받은 내용 그대로). 요구사항의 기준 문서입니다.

## 1. 프로젝트 목적

스마트폰 한 대를 두 사람 사이에 놓고 사용하는 대면 실시간 음성 통역 앱을 개발한다.

사용자가 한국어로 말하면 상대방 언어로 번역하고, 상대방이 외국어로 말하면 한국어로 번역한다.

번역 결과는 텍스트와 음성으로 제공하며, 음성 출력은 앱 소유자의 목소리를 기본으로 한다. 상대방도 원하는 경우 자신의 목소리를 별도로 등록하여 사용할 수 있도록 한다.

본 프로젝트는 업체 의뢰 없이 개인이 개발하고 지인들과 공유하는 것을 목적으로 한다.

## 2. 확정 요구사항

### 2-1. 앱 형태
- 모바일 웹앱(PWA)
- Android 및 iPhone 지원
- 홈 화면 설치 지원
- 회원가입 및 로그인 없음
- 개인정보 입력 없음
- 개인 계정 서버 없음
- 지인에게 링크를 공유하여 사용할 수 있는 구조

### 2-2. 사용 방식
- 스마트폰 한 대를 두 사람 사이에 놓고 사용
- 두 사람은 한 기기의 화면을 공유
- 한 번에 한 사람씩 말하는 교대 발화 방식
- A 측과 B 측 발화 버튼을 구분
- 발화 방향에 따라 자동으로 번역 방향 설정
- 동시 발화 및 화자 자동 분리 기능은 1차 개발에서 제외

### 2-3. 지원 언어
초기 지원 언어:
- 한국어
- 일본어
- 영어
- 중국어(표준 중국어, 간체 기준으로 시작)

총 12개 방향의 번역을 지원한다.

한국어↔일본어, 한국어↔영어, 한국어↔중국어뿐 아니라 일본어↔영어, 일본어↔중국어, 영어↔중국어도 지원한다.

언어 간 직접 번역 모델이 적절하지 않으면 중간 언어를 경유하는 방법도 검증하되, 번역 품질이 저하되는 경우 직접 번역을 우선한다.

### 2-4. 음성 복제
- 앱 소유자 음성을 기본 음성으로 등록
- 상대방 음성은 선택적으로 등록
- 상대방 음성 등록 전 동의 확인
- 각 음성 프로필은 기기 내부에만 저장
- 통역 시 출력 목소리를 선택할 수 있어야 함
- 원본 음성 및 음성 임베딩의 외부 전송 금지
- 프로필 삭제 기능 제공

## 3. 가장 중요한 개발 원칙: 완전한 로컬 AI 처리

본 앱은 음성 관련 데이터의 클라우드 전송을 허용하지 않는다.

다음 처리는 전부 스마트폰 내부에서 실행해야 한다.

1. 마이크 음성 입력
2. 음성 인식(STT/ASR)
3. 언어 번역
4. 음성 복제
5. 음성 합성(TTS)
6. 음성 재생

외부 서버는 앱 파일과 공개 AI 모델을 최초 다운로드하는 용도로만 사용한다.

금지 사항:
- OpenAI API 등 외부 음성 인식 API 사용 금지
- Google Translate 등 외부 번역 API 사용 금지
- ElevenLabs 등 외부 음성 합성 API 사용 금지
- 음성 파일 업로드 금지
- 음성 임베딩 전송 금지
- 대화 내용 서버 저장 금지
- 사용자 계정 생성 금지
- Supabase Auth, Firebase Auth 등 인증 기능 도입 금지
- Analytics 및 광고 추적 SDK 사용 금지
- 외부 CDN 폰트 및 불필요한 외부 스크립트 사용 금지

앱 정적 파일과 공개 모델 가중치의 최초 다운로드는 허용한다. 다운로드 완료 후 오프라인에서도 핵심 통역 기능이 작동하도록 한다.

## 4. 기술 아키텍처

전체 처리 구조:

스마트폰 마이크
→ 음성 구간 감지(VAD)
→ 음성 인식(ASR)
→ 로컬 번역
→ 로컬 음성 합성(TTS)
→ 스마트폰 스피커 출력

### 4-1. 프런트엔드
- TypeScript
- React
- Vite
- PWA
- Service Worker
- Web Audio API
- getUserMedia
- IndexedDB
- OPFS 검토

화면은 모바일 우선으로 설계한다.

### 4-2. 음성 인식(ASR)

우선 검토 대상:
- whisper.cpp WebAssembly
- Whisper 계열 WebGPU 실행 방식
- 기타 브라우저에서 로컬 실행 가능한 다국어 ASR 모델

필수 조건:
- 한국어, 일본어, 영어, 중국어 인식
- 네트워크 없이 추론 가능
- Android 및 iPhone 브라우저에서 실행 가능
- 음성 입력 데이터 외부 전송 없음
- 발화 종료 후 가능한 빠르게 결과 제공

주의:
whisper.cpp의 브라우저 WASM 예제는 모델에 따라 실시간보다 느릴 수 있으므로 그대로 채택하지 않는다. 실제 기기에서 속도를 비교하고, 통역에 적합한 모델을 선정한다.

### 4-3. 번역 엔진

우선 검토:
- Transformers.js
- ONNX Runtime Web
- WebGPU 및 WASM 지원 다국어 번역 모델

필수 조건:
- 네 언어 간 12개 방향 지원
- 외부 서버 호출 없이 로컬 번역
- 짧은 대화 문장에 적합한 번역 품질
- 모델 파일을 기기에 저장하여 재사용 가능

모델을 임의로 확정하지 않는다.

먼저 후보 모델을 비교하여 언어별 번역 품질, 메모리 사용량, 처리 속도를 측정한 뒤 채택한다.

### 4-4. 음성 합성 및 복제(TTS)

최우선 검증 모델:
- Zyphra ZONOS3-Mini

공식 자료:
https://github.com/Zyphra/ZONOS3-Mini
https://www.zyphra.com/our-work/zonos3-mini

선정 이유:
- 제로샷 음성 복제 지원
- 한국어, 일본어, 영어, 중국어 지원
- 브라우저 WebGPU 실행 환경 제공
- 모델 가중치 Apache 2.0 라이선스
- 기기 내부 음성 합성 구조 지원

구현 요구:
- 브라우저 WebGPU 기반 로컬 실행
- 음성 등록 및 임베딩 생성
- 등록된 음성 프로필 선택
- 번역문을 선택된 목소리로 합성
- 음성 출력은 가능한 스트리밍 방식으로 구현
- 네트워크로 음성 또는 임베딩을 전송하지 않음

공식 모델을 직접 연동하기 전에 실제 PWA 환경에서 동작하는지 별도 테스트한다.

### 4-5. 로컬 저장 구조

IndexedDB 또는 OPFS에 다음 데이터를 저장한다.

- 앱 설정
- 언어 설정
- A/B 언어 조합
- 음성 프로필 메타데이터
- 음성 임베딩
- 모델 다운로드 상태
- 모델 파일 또는 모델 캐시

원본 음성은 음성 프로필 생성에 필요한 동안만 처리하고, 기본적으로 영구 보관하지 않는다. 사용자가 명시적으로 보관을 선택하는 경우에만 저장한다.

음성 임베딩은 앱 소유자와 상대방의 프로필을 구분하여 저장한다.

기기 데이터 삭제 시 프로필 복구가 불가능하다는 점을 안내한다.

## 5. UI/UX 설계

화면은 가능한 단순하게 구성한다.

### 5-1. 최초 실행
- 앱 소개
- 마이크 권한 안내
- 지원 기기 확인
- AI 모델 다운로드 안내
- 기본 언어 설정
- 앱 소유자 음성 등록 안내

### 5-2. 음성 등록 화면

기본 프로필:
- 앱 소유자
- 음성 녹음 시작
- 녹음 완료
- 음성 프로필 생성
- 테스트 음성 재생

선택 프로필:
- 상대방 음성 추가
- 동의 확인
- 음성 녹음
- 프로필 생성
- 프로필 삭제

녹음은 충분한 음성 샘플을 확보할 수 있도록 안내하되, 최적 녹음 시간은 실제 ZONOS3-Mini 시험으로 결정한다.

### 5-3. 메인 통역 화면

상단:
- 앱 이름
- 설정 버튼
- 로컬 처리 상태

중앙:
- A 측 언어
- B 측 언어
- 언어 변경 버튼

하단:
- A 측 발화 버튼
- B 측 발화 버튼
- 통역 중 상태
- 번역 결과 텍스트
- 음성 재생 버튼
- 출력 목소리 선택
- 통역 종료 버튼

각 발화 버튼은 크게 만들어야 한다.

두 사람 모두 화면을 쉽게 볼 수 있도록 버튼을 좌우로 배치한다.

### 5-4. 통역 결과 표시

각 대화는 다음 순서로 표시한다.

- 발화자
- 원문
- 번역문
- 음성 재생 상태

대화 내역을 계속 누적하여 보여줄 수 있지만, 기본적으로 대화 기록을 서버에 저장하지 않는다.

대화 내역 삭제 기능을 제공한다.

## 6. 통역 동작 로직

### A 측 발화
1. A 측 버튼을 누른다.
2. 마이크 녹음을 시작한다.
3. 발화 종료를 감지한다.
4. ASR로 원문을 인식한다.
5. A 측 언어에서 B 측 언어로 번역한다.
6. 선택된 음성 프로필로 번역문을 합성한다.
7. 번역문을 화면에 표시한다.
8. 번역 음성을 재생한다.
9. 재생 종료 후 다음 발화를 기다린다.

### B 측 발화
1. B 측 버튼을 누른다.
2. 마이크 녹음을 시작한다.
3. 발화 종료를 감지한다.
4. ASR로 원문을 인식한다.
5. B 측 언어에서 A 측 언어로 번역한다.
6. 선택된 음성 프로필로 번역문을 합성한다.
7. 번역문을 화면에 표시한다.
8. 번역 음성을 재생한다.
9. 재생 종료 후 다음 발화를 기다린다.

### 발화자별 음성 선택

번역 방향과 음성 프로필은 독립적으로 관리한다.

예를 들어:
- A 측 한국어 발화 → 일본어 번역 → 앱 소유자 목소리 출력
- B 측 일본어 발화 → 한국어 번역 → 앱 소유자 목소리 출력
- B 측 일본어 발화 → 한국어 번역 → 상대방 목소리 출력

이 선택은 통역 중에도 변경할 수 있어야 한다.

## 7. 오디오 처리 및 에코 방지

한 대의 스마트폰으로 통역하므로 스피커 출력이 마이크에 재입력되는 문제를 반드시 방지한다.

초기 구현:
- 한 번에 한 사람씩 발화
- 녹음 완료 후 음성 처리
- 번역 음성 재생 중에는 마이크 녹음을 중단
- 재생 완료 후 다음 녹음 시작
- 마이크 입력 및 출력 상태를 UI로 표시
- 재생 중 재녹음이 발생하지 않도록 상태 제어
- 사용자가 통역을 중단할 수 있도록 구현

추후 개선:
- Acoustic Echo Cancellation
- Noise Suppression
- Automatic Gain Control
- Web Audio API 기반 입력 레벨 조정

동시 발화 인식은 1차 개발에서 제외한다.

## 8. 모델 다운로드 및 오프라인 처리

최초 실행:
1. 앱 정적 파일 다운로드
2. 기기 성능 확인
3. WebGPU 지원 확인
4. ASR 모델 다운로드
5. 번역 모델 다운로드
6. TTS 모델 다운로드
7. 저장 상태 확인
8. 테스트 음성 생성
9. 통역 사용 가능 상태로 전환

모델 다운로드는 사용자가 진행 상황을 확인할 수 있어야 한다.

모델별 다운로드 크기, 예상 저장 용량, 다운로드 상태를 표시한다.

다운로드 도중 앱이 종료되어도 재시도할 수 있어야 한다.

오프라인 모드:
- 다운로드 완료된 모델 사용
- 음성 인식
- 번역
- 음성 합성
- 음성 재생
모두 외부 연결 없이 실행되어야 한다.

모델 업데이트는 사용자가 선택하여 진행할 수 있도록 한다.

## 9. 기기 호환성 및 예외 처리

Android와 iPhone을 모두 지원하되, 모든 기기에서 동일한 성능이 보장된다고 가정하지 않는다.

다음 항목을 기기별로 확인한다.

- WebGPU 지원
- WASM 지원
- 메모리 사용량
- 모델 다운로드 및 저장
- 마이크 권한
- 스피커 출력
- 브라우저 백그라운드 동작
- 장시간 실행 시 발열
- 배터리 소모
- 화면 잠금 시 통역 유지 여부

WebGPU 미지원 기기는 지원 불가 또는 제한 모드로 구분한다.

지원하지 않는 기능을 작동하는 것처럼 표시하지 않는다.

브라우저가 백그라운드로 전환되거나 화면이 꺼질 때 통역이 중단될 수 있으므로, 통역 중 화면 유지 안내를 제공한다.

## 10. 개발 단계

### Phase 0: 기술 검증
가장 먼저 수행한다.

1. ZONOS3-Mini 공식 WebGPU 실행 환경 확인
2. Android Chrome 실행 테스트
3. iPhone Safari 실행 테스트
4. 네 언어 TTS 테스트
5. Whisper WASM/WebGPU ASR 후보 비교
6. 네 언어 인식 품질 테스트
7. 로컬 번역 후보 비교
8. 12개 방향 번역 테스트
9. 메모리 및 처리 시간 측정
10. 음성 데이터 외부 전송 여부 확인

이 단계에서 성능이 부족한 모델은 교체한다.

### Phase 1: 기본 PWA
- PWA 구성
- 메인 UI
- 언어 선택
- A/B 발화 구분
- 마이크 녹음
- 원문 표시
- 번역문 표시

## 12. 개발 시 반드시 지켜야 할 사항

1. 전체 앱을 만들기 전에 Phase 0 기술 검증을 완료한다.
2. 실제 스마트폰에서 실행하지 않은 기능을 완료했다고 보고하지 않는다.
3. 외부 AI API를 임의로 연결하지 않는다.
4. 음성 데이터가 외부로 나가지 않는지 네트워크 검사로 확인한다.
5. 모델의 라이선스와 사용 조건을 확인한다.
6. 모델 크기와 메모리 요구량을 기록한다.
7. iPhone과 Android의 호환성을 별도로 검증한다.
8. 기존 코드가 있다면 먼저 구조를 분석하고 기존 기능을 임의로 삭제하지 않는다.
9. 오류 발생 시 원인을 확인한 뒤 수정한다.
10. 각 Phase가 완료될 때마다 테스트 결과와 미해결 사항을 보고한다.

## 13. 1차 개발 제외 사항

다음 기능은 1차 개발에서 제외한다.

- 원격 통역
- WebRTC
- 다자간 통역
- 동시 발화 자동 분리
- 회원가입 및 로그인
- 서버 기반 사용자 계정
- 클라우드 음성 저장
- 통역 기록 서버 동기화
- 유료 구독 및 결제

단, 추후 원격 통역을 추가할 수 있도록 음성 입력, ASR, 번역, TTS 기능은 독립 모듈로 구성한다.

## 14. 최종 개발 목표

사용자가 앱을 실행하고 두 사람이 언어를 선택하면 바로 대화를 시작할 수 있어야 한다.

앱 소유자는 자신의 목소리로 번역 음성을 들려줄 수 있고, 상대방도 자신의 목소리를 등록하면 선택적으로 해당 목소리를 사용할 수 있어야 한다.

모든 음성 관련 처리는 스마트폰 내부에서 실행하며, 모델 최초 다운로드 이후에는 인터넷 연결 없이도 통역이 가능해야 한다.

가장 중요한 것은 기능의 개수가 아니라 다음 세 가지다.

1. 실제 대화에서 사용할 수 있는 통역 속도
2. 자연스럽고 정확한 번역
3. 음성 데이터가 외부로 유출되지 않는 로컬 처리

위 목표를 기준으로 개발을 진행한다.
