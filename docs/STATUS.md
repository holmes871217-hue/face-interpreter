## 지금까지 결과 요약 (자세한 내용: PHASE0_REPORT.md 8장)
- 외부 전송: 서비스워커·CSP 차단 동작 확인(개발 서버). 휴대폰에서도 재확인 필요.
- TTS(ZONOS3-Mini, 갤럭시):
  - 첫 소리 약 0.5초, 실시간보다 빠름(LACI 끔).
  - LACI 켜면 길이 정상화(영어 68초 폭주 해소), 대신 첫 소리 0.7~3.7초로 느려짐.
  - 언어별 기본 음성으로 바꾼 뒤 한·일·영 발음 "괜찮음"(소유자 청취).
  - **중국어: 휴대폰에서만 불안정** — 같은 시드인데 매번 길이(2.4~4.9초)·음량(-60~-16 dB) 다름, 잘림/너무 빠름/뭉개짐. 개발 서버에선 정상(음성인식으로 원문 일치 확인).
- ASR(개발 서버, 합성음 입력): Whisper base 일·영 정확, 한국어 1어절 오류, 중국어 번체 출력. Moonshine 중·일 정확, 한국어 실패.
- 번역(개발 서버): M2M100 품질 부족(`<unk>`, 반복 루프). Hy-MT3는 아직 미실행(휴대폰에서 시험 필요).

## 중국어 진단(A~F) 결과 (갤럭시, 2회 실행, 캡처 기준. B행은 캡처에 없음)
| 조건 | 1회차 | 2회차 |
| --- | --- | --- |
| A 여자(Meilin)+LACI 시드1 | 0.9 s, -20 dB | 3.0 s, -28 dB |
| F = A와 완전히 같은 조건 | 1.3 s, -17 dB | 0.9 s, -23 dB |
| E 여자+LACI 시드2 | 5.0 s, -19 dB | 1.3 s, -25 dB |
| C 남자(Haoran)+LACI | 3.5 s, -24 dB | 4.5 s, -20 dB |
| D 남자, LACI 끔 | (캡처 없음) | 7.1 s, **-46 dB 거의 무음** |

- 정상 길이는 약 3.5 s(개발 서버 재현값).
- **같은 조건(A와 F)인데 결과가 다름** → 휴대폰 GPU에서 실행마다 결과가 달라짐 [확인]. 원인(엔진 연산 순서, Adreno 드라이버 등)은 미확인.
- 여자 목소리는 6번 중 4번이 0.9~1.3 s로 잘림. 남자 목소리+LACI는 2번 모두 정상 길이에 가까움(표본 2개라 결론 아님).
- LACI를 켜도 잘림이 생김 → 휴대폰에서 LACI가 조기 종료를 다 막지 못함 [확인].

## 안정 모드 추가 (2026-11-27)
- 소유자 피드백: "영어·일본어·중국어 다 안 된다, 잘 되는 걸 보여 달라".
- 조치: 합성을 다 만든 뒤 길이(언어별 말 속도 기준 예상 길이의 0.6~1.8배)·음량(-40 dB 이상)·NaN을 검사,
  불합격이면 시드를 바꿔 최대 4번 다시 만들고 통과한 것만 재생. 합성·음성 탭과 통합 통역 탭 기본값.
- 대가: 스트리밍을 포기하므로 첫 소리가 늦어짐(문장 하나 다 만드는 시간 + 재시도 시간).
- 검사 기준은 갤럭시 측정값으로 맞춤: 잘린 중국어 0.9 s, 무음 -46 dB, 늘어진 영어 17.5/68.6 s는 걸러지고 정상 결과는 통과.
- 한계: 길이·음량만 보므로 "길이는 맞는데 발음이 뭉개진" 결과는 못 거름 → 필요하면 기기 내 ASR로 내용 확인 단계 추가 검토.

## 갤럭시 원클릭 테스트 1회차 (버전 57b46b1)
- 엔진 로드 37초 만에 `GPU device lost: vkQueueSubmit failed with VK_ERROR_DEVICE_LOST` (Dawn/Vulkan). 합성 0건.
- 이전 세션에서는 같은 기기에서 엔진 로드가 여러 번 성공 → 항상 나는 오류는 아님. 원인(메모리 압박, 발열, 특정 커널의 GPU 타임아웃 등) 미확인.
- 조치: device lost가 나면 페이지를 자동 새로고침하고 엔진을 다시 로드(최대 2회). 결과·에러 기록은 sessionStorage에 남겨 재시작 후에도 복사됨.

- 2회차도 같은 오류(로드 시작 28초 후). 그런데 보고서 버전이 57b46b1 → GitHub Pages `max-age=600` 때문에 새 배포가 최대 10분 늦게 반영됨.
  서비스워커가 페이지·sw.js를 항상 재검증(`cache: no-cache`)하도록 수정. 로드 실패 시 경과 시간·마지막 진행 상태를 메모로 남김.

- 3회차(새 버전 0ca1249): 실패 시점 38초, 가중치 878/878 MB 로드 완료 후(저장소에서, 네트워크 0 MB) device lost.
  → 가중치 이후 단계 = 코덱 커널 시간 측정(f16 "h8" 후보 실행) 또는 예열(309행 레퍼런스 prefill, CFG 쌍)로 좁혀짐.
- 조치: 공식 엔진에 패치(`bench/vendor/zonos3-engine/patches/0001-...`): 시작 단계 보고 + 가벼운 시작
  (`zacq8=1` q8 코덱 고정, `warm=min` 최소 예열). 앱 기본값을 가벼운 시작으로, `?engine=full`이면 원래 방식.
- 개발 서버에서 발견: 엔진이 시작할 때마다 기본 음성 등 작은 파일 ~170개를 HF에서 매번 받음(캐시 안 함)
  → 반복 실행 시 HF 429로 엔진 시작 실패, 오프라인 시작 불가. 서비스워커가 고정 리비전의 작은 파일을 캐시하도록 수정.

## 첫 성공: 가벼운 시작 + 안정 모드 (버전 57673d2, 갤럭시 S22 울트라)
- 엔진 로드 성공 29초(저장된 모델 사용), 에러 없음 → device lost 원인은 코덱 커널 시험 또는 무거운 예열 쪽이었을 가능성 높음 [추정, 둘 중 무엇인지는 미분리].
- 4개 언어 모두 첫 시도에 검사 통과:

| 언어 | 목소리 | 길이 | 음량 | 준비까지 |
| --- | --- | --- | --- | --- |
| ko | Seoyeon | 4.2 s | -25 dB | 8.7 s |
| ja | Seoyeon | 4.9 s | -30 dB | 5.7 s |
| en | Savannah | 3.7 s | -32 dB | 7.1 s |
| zh | Meilin | 2.0 s | -33 dB | 2.2 s |

- 주의: 중국어 2.0 s는 정상(약 3.5 s)보다 짧음 → 검사 하한(예상의 0.6배)을 겨우 넘김. 뒷부분 잘림 가능성 [청취 확인 필요].
- 준비까지 5.7~8.7 s: 대화에 쓰기엔 느림. 스트리밍 포기 + LACI + q8 코덱 영향으로 추정 → 다음 개선 대상.

- 소유자 청취(57673d2, q8 코덱): **"안 들려, 음성이 다 깨졌어"** (4개 언어 모두).
- 개발 서버 비교: q8 코덱과 시간측정(h8) 코덱이 같은 소리를 냄, 한국어는 Whisper가 원문대로 받아씀
  → q8 코덱 경로가 **갤럭시(Adreno)에서만** 소리를 망가뜨린다고 판단 [추정: 기기에서 두 방식 비교 청취로 확인 필요].
- 조치: 시작 방식 선택(합성·음성 탭). 기본 'tuned'(코덱 시간측정 O, 최소 예열). 시간측정 단계에서 device lost면
  자동 재시작 때 'fixed'(h8 커널 고정: gemm_h8_ks4 / gemm_h8_r8_8x8)로 전환. 'q8'은 선택 가능하나 깨짐 경고.
- 결과 복사에 실제 사용된 코덱 커널이 기록됨.
